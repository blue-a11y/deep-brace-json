# DeepBrace JSON 开发规划

> 本文档只记录未实现、进行中或待验收的工作。当前顶层能力见双语 README，具体行为由源码和浏览器验收
> 确认，历史开发流水以 Git 为准。

## 规划规则

- 每个工作项使用稳定规划 ID，并清楚描述范围、目标与验收标准。
- 规划项“完成”需要满足目标结果、与风险相称的浏览器验收和必要文档联动，不能只以代码写完判断。
- 完成后的工作项从当前规划移除；如果改变 README 顶层能力，同时同步英文和简体中文 README。
- 规划状态只使用：`待决策`、`待开始`、`进行中`、`验收中`、`已阻塞`。完成项从当前规划移除，结果由源码、浏览器验收证据、必要的 README 摘要和 Git 保存。
- 候选需求不代表已经承诺开发；进入当前规划前必须补齐范围与验收标准。

## 当前阶段目标

当前阶段聚焦“本地数据可靠性与可验证性”：完成 IndexedDB v3 结构化持久化交付，修正与实际行为冲突的产品语义，并为解析、标签、响应式和重置链路建立可重复的手工验收基线。

## 当前规划

### `PLAN-001` IndexedDB v3 持久化整体验收

- **状态**：验收中。
- **优先级**：P0。
- **目标**：以无 `keyPath` 的 Object Store 保存应用状态和滚动，分栏独立保存在 localStorage 并供骨架首帧同步读取，确保启动恢复、重置、撤销和刷新之间没有竞态。
- **数据与恢复验收清单**：
  - v2 打开 v3 后重建三个 Store，且均为 out-of-line key。
  - 用真实上一版 v2 数据启动当前版本，确认三个旧 Store 已重建且旧数据均未保留，符合当前“不迁移”策略。
  - 应用状态 record root 不重复保存 Object Store primary key 或额外 `state` 包装；标签业务 ID
    正常保留，structured clone 类型不丢失。
  - 滚动使用 `[tabId, area]` 复合外部键；分栏使用独立 localStorage，旧 v3 布局仅在写入新来源成功后删除。
  - 重置和撤销在 React 重挂载前同步切换滚动与布局内存缓存，并同步更新布局 localStorage。
  - 重置 / 撤销的完成 Promise 覆盖会影响立即刷新结果的应用状态、滚动写入和旧布局清理；不得只有滚动
    adapter 提供写入屏障。
  - IndexedDB 验收隔离数据库与页面状态，并覆盖失败、连续写和重置 / 撤销
    交错。
- **浏览器验收**：构造多标签、暗色、非默认代码字体、8 空格、自定义主题、关闭长字符串、80/20 分栏和双区非零滚动；验证重置为默认、8 秒内撤销、刷新后仍保持撤销结果。
- **当前进度**：真实页面的多标签、偏好、分栏与双区滚动刷新恢复按上述浏览器场景手工验收；其余数据与恢复
  边界仍需按清单验证。
- **边界**：按当前产品决定，不迁移旧 localStorage 或未发布的 v1 / v2 IndexedDB 数据。

### `PLAN-002` 统一重置文案与 Modal 动作约定

- **状态**：待开始。
- **优先级**：P0。
- **现状**：确认弹窗写“此操作不可撤销”，实际重置后 8 秒内可以完整撤销；设置 Modal 还使用 Footer 承载即时危险操作，需要与根 `AGENTS.md` 的 Modal 约定统一解释或调整结构。
- **验收标准**：
  - 确认文案准确说明重置范围和 8 秒撤销窗口。
  - 设置 Modal 不出现仅用于关闭的 Footer 或“完成”按钮。
  - 危险操作的入口、二次确认、关闭行为和键盘焦点符合统一 Modal 约定。
  - 如果改变 README 中的顶层能力描述，同步更新英文和简体中文版本。

### `PLAN-003` 明确并统一“全局缩进”作用范围

- **状态**：待决策。
- **优先级**：P0。
- **现状**：2 / 4 / 8 空格设置会影响树几何和复制序列化，但编辑器“格式化”固定使用 2 空格；“全局缩进”名称容易产生会影响格式化的预期。
- **决策选项**：
  1. 让格式化读取全局缩进，保持“全局”语义。
  2. 保持格式化固定 2 空格，并把设置名称和说明收敛为“树与复制缩进”。
- **验收标准**：选定一种语义后，按钮提示、设置名称、实现和 README 摘要完全一致；2 / 4 / 8 三档均验证。

### `PLAN-006` 建立浏览器手工验收矩阵

- **状态**：进行中。
- **优先级**：P1。
- **范围**：
  - 首屏健康、JSON5 与嵌套解析、偏好和双区滚动刷新恢复、多标签重置 / 撤销与分栏恢复。
  - 长字符串在 120 / 121 字符边界的截断、全文弹层高度与滚动。
  - 树单节点和全部折叠、稳定行号、换行 / 横向滚动、逐节点和整树复制。
  - 339/340、479/480、559/560、599/600、679/680、767/768、799/800、859/860px 关键宽度。
  - 工具菜单与直显动作功能等价，图标和 Logo 不压缩、不换行。
  - 编辑器 / 树滚动、分栏拖拽、刷新、移动端切换、重置和撤销。
  - 非活动 / 活动标签与批量关闭撤销后的滚动落库、刷新恢复；编辑后未解析刷新时清除旧树折叠状态。
  - 快捷键聚焦保留选区、重命名、左右插入、批量关闭撤销；修饰键提示、刷新、重置与撤销恢复；
    桌面与窄屏弹层、菜单和输入框保护。
  - 真实剪贴板粘贴约 1 MB / 10 MB、后台解析、虚拟树挂载数量、末尾可达、长值预览与完整复制；
    动态行高、标签切换、刷新锚点、字体 / 换行 / 视口变化及键盘折叠。
  - 普通 / 约 1 MB / 约 10 MB 示例菜单的桌面与窄屏入口、键盘选择与刷新恢复；大纲行号四位数不换行。
- **待处理边界**：800 条记录（紧凑文本约 11.5 万字符）的文档刷新时会触发 CodeMirror 的
  `Measure loop restarted more than 5 times` 警告，格式化后也可复现，需继续定位编辑器布局与滚动恢复。
  系统保留快捷键及其他浏览器差异仍待验收。
- **验收标准**：保留可重复的手工步骤、初始状态、视口、预期和实际结果；按变更范围执行相关场景。

### `PLAN-007` 清理状态生命周期边界

- **状态**：待开始。
- **优先级**：P2。
- **现状**：关闭标签后，对应的 IndexedDB 滚动记录不会立即删除；多个页面之间也不会实时同步状态。
- **验收标准**：决定孤立滚动记录的清理时机并覆盖撤销关闭场景；明确多页面并发是支持、提示还是不处理，避免无界增长和误覆盖。

### `PLAN-008` 建立生产包体与首屏性能预算

- **状态**：进行中。
- **优先级**：P2。
- **现状**：品牌动效延迟加载及静态降级、非阻塞字体和 HTML 响应式骨架屏已实现。
  CodeMirror 与设置、主题、快捷键弹窗保持直接加载，打开弹窗不依赖额外脚本下载；
  HeroUI 弹窗外壳保留焦点上下文，并覆盖桌面与窄屏首次打开、关闭和快捷键重开。
  非阻塞 CSS 下载与挂载前样式屏障已实现；手工验收需覆盖启动与动态资源慢加载、失败重试，
  以及骨架到首帧和品牌动效接入的布局变化。
  主 JavaScript chunk 仍超过 Vite 默认 500kB 提示阈值；
  还需定义固定环境下的包体、首屏加载和交互就绪预算并接入 CI，并扩充线上多地区冷 / 热缓存采样。
  线上已确认骨架不再等待主 CSS；域名已切回 Vercel DNS 并直连 Vercel，网络传输波动仍需独立排查，
  不以单次测速或 Vercel 缓存命中代表整条链路性能。
- **验收标准**：先建立可重复的产物大小和首屏指标，再决定代码分割或依赖拆分策略；优化后不得以隐藏警告代替指标改善，并记录对 CodeMirror、HeroUI 和主题资源加载的影响。

## 明确暂不纳入

- 不迁移旧 localStorage、IndexedDB v1 或未发布的 v2 数据；升级到 v3 可以清空旧本地状态。
- 不增加云同步、账号系统或把用户 JSON 上传到服务端的能力。
- 不把提交批次、排障流水或已经完成的功能长期堆放在本规划中。
