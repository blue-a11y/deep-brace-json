# DeepBrace JSON 开发规划

> 本文档只记录未实现、进行中或待验收的工作。当前顶层能力见双语 README，具体行为由源码和测试
> 验证，历史开发流水以 Git 为准。

## 规划规则

- 每个工作项使用稳定规划 ID，并清楚描述范围、目标与验收标准。
- “完成”必须同时满足代码、自动化检查、必要的浏览器验收和文档联动，不能只以代码写完或测试通过判断。
- 完成后的工作项从当前规划移除；如果改变 README 顶层能力，同时同步英文和简体中文 README。
- 规划状态只使用：`待决策`、`待开始`、`进行中`、`验收中`、`已阻塞`。完成项从当前规划移除，结果由源码、测试、必要的 README 摘要和 Git 保存。
- 候选需求不代表已经承诺开发；进入当前规划前必须补齐范围与验收标准。

## 当前阶段目标

当前阶段聚焦“本地数据可靠性与可验证性”：完成 IndexedDB v3 结构化持久化交付，修正与实际行为冲突的产品语义，并为解析、标签、响应式和重置链路建立可重复的回归基线。

## 当前规划

### `PLAN-001` IndexedDB v3 持久化整体验收

- **状态**：验收中。
- **优先级**：P0。
- **目标**：以三个无 `keyPath` 的 Object Store 保存应用状态、分栏和滚动，确保启动恢复、重置、撤销和刷新之间没有竞态。
- **自动化验收**：
  - v2 打开 v3 后重建三个 Store，且均为 out-of-line key。
  - v2 fixture 与真实上一版 schema 一致，向三个旧 Store 写入探针数据；升级后断言 Store 已重建且
    旧数据均未保留，明确证明当前“不迁移”的清空策略。
  - 应用状态 record root 不重复保存 Object Store primary key 或额外 `state` 包装；标签业务 ID
    正常保留，structured clone 类型不丢失。
  - 滚动使用 `[tabId, area]` 复合外部键，分栏在 IndexedDB 中保存对象。
  - 重置和撤销在 React 重挂载前同步切换滚动与布局内存缓存。
  - 重置 / 撤销的完成 Promise 覆盖会影响立即刷新结果的应用状态、滚动和布局写入；不得只有滚动
    adapter 提供写入屏障。
  - IndexedDB 用例显式隔离数据库与模块缓存，不依赖执行顺序，并覆盖失败、连续写和重置 / 撤销
    交错。
- **浏览器验收**：构造多标签、暗色、8 空格、自定义主题、关闭长字符串、80/20 分栏和双区非零滚动；验证重置为默认、8 秒内撤销、刷新后仍保持撤销结果。
- **当前自动化进度**：已覆盖多标签、长字符串偏好、非默认分栏、双区非零滚动、app-state 显式
  写入屏障、滚动 / 布局重置恢复事务、重置 / 撤销 action Promise 对 app-state 屏障的等待，以及
  撤销完成后立即刷新恢复；暗色、8 空格、自定义主题和精确 80/20 边界仍待补齐。
- **边界**：按当前产品决定，不迁移旧 localStorage 或未发布的 v1 / v2 IndexedDB 数据。

### `PLAN-002` 统一重置文案与 Modal 动作约定

- **状态**：待开始。
- **优先级**：P0。
- **现状**：确认弹窗写“此操作不可撤销”，实际重置后 8 秒内可以完整撤销；设置 Modal 还使用 Footer 承载即时危险操作，需要与根 `AGENTS.md` 的 Modal 约定统一解释或调整结构。

  - 设置 Modal 不出现仅用于关闭的 Footer 或“完成”按钮。

  - 如果改变 README 中的顶层能力描述，同步更新英文和简体中文版本。

### `PLAN-003` 明确并统一“全局缩进”作用范围

- **状态**：待决策。
- **优先级**：P0。
- **现状**：2 / 4 / 8 空格设置会影响树几何和复制序列化，但编辑器“格式化”固定使用 2 空格；“全局缩进”名称容易产生会影响格式化的预期。
- **决策选项**：
  1. 让格式化读取全局缩进，保持“全局”语义。
  2. 保持格式化固定 2 空格，并把设置名称和说明收敛为“树与复制缩进”。
- **验收标准**：选定一种语义后，按钮提示、设置名称、实现、测试和 README 摘要完全一致；2 / 4 / 8 三档均验证。

## 明确暂不纳入

- 不迁移旧 localStorage、IndexedDB v1 或未发布的 v2 数据；升级到 v3 可以清空旧本地状态。
- 不增加云同步、账号系统或把用户 JSON 上传到服务端的能力。
- 不把提交批次、排障流水或已经完成的功能长期堆放在本规划中。

## 质量门禁

完整规则和自动检查边界见 [docs/DEVELOPMENT.md](DEVELOPMENT.md)。

### 自动化检查

每个功能批次至少执行：

```bash
pnpm test
pnpm lint
pnpm build
git diff --check
```

根据变更范围增加针对性测试；已有测试通过不等于未覆盖的浏览器交互已经验证。

### 浏览器验收基线

涉及对应功能时至少覆盖：

1. JSON、JSON5、普通文本和非法 JSON。
2. 格式化、压缩、连续转义 / 反转义，以及嵌套 `Parse`。
3. 多标签的新建、切换、关闭、撤销关闭和刷新恢复。
4. 编辑器 / 树滚动位置、50/50 与自定义分栏比例。
5. 设置、长字符串 120 / 121 边界、重置、8 秒撤销和再次刷新。
6. 工具栏关键断点、溢出菜单等价性和 767 / 768px 布局切换。
7. CodeMirror、Modal、Select、Dropdown 聚焦时的快捷键行为。

### 文档联动

完成前逐项确认：

- 当前行为、默认值、边界和持久化范围已有对应测试或浏览器验收证据。
- 顶层能力、技术栈、脚本或启动命令变化时，两版 README 的结构和内容同步。
- 当前规划状态已更新；完成项不继续留在“当前规划”。
- 专项文档中的“当前状态”没有与源码产生冲突。

## 完成流转

```text
规划项明确范围与验收
  → 实现并补测试
  → 自动化检查
  → 按功能范围完成浏览器验收
  → 更新必要的双语 README 与专项文档
  → 从 docs/ROADMAP.md 当前规划移除
  → 由 Git 保存交付历史
```
